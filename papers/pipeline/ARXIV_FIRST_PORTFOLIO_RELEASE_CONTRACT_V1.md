# ORION-V2 arXiv-First Portfolio Release Contract V1

## Purpose

Every surviving paper will be posted to arXiv before journal submission when the human authors choose to release it. This contract prevents the preprint from becoming a lower-rigor or scientifically different version.

## 1. One science object, versioned exposition

For each paper:

```text
verified scientific master
-> arXiv preprint
-> journal adaptation
```

The arXiv version freezes the scientific identity available at that time. A journal version may correct, narrow, clarify, reanalyse valid existing evidence, or add genuinely new prospectively obtained evidence with explicit versioning. It may not silently rewrite the original study history.

## 2. Portfolio-specific arXiv readiness

### P-D

### #51 LLM Prospective Revision Audit

Separate branch contract. Because the paper's central evidence is theorem/proof based and the finite mechanical support already exists, it is closest to actual arXiv release.

## 3. Public-preprint scientific gate

Every arXiv manuscript requires:

- atomic claim inventory completed for the exact public bytes;
- all literature/priority statements bound to verified sources;
- result values bound to immutable receipts;
- theorem statements bound to complete proof/counterexample checks;
- adverse/null/CANNOT_CHECK results visible where claim-relevant;
- Methods statements reconciled to actual conduct;
- data and analysis identities reconciled;
- figures/tables bound to source data and analysis receipts;
- no authoring placeholders in public prose;
- no internal repository-development language except in a separate reproducibility appendix when scientifically useful;
- transparent AI-assistance statement;
- human author adoption/approval.

## 4. arXiv metadata fields requiring humans

The manuscript-development AI may draft but may not decide:

- author list/order;
- corresponding contact;
- subject category/cross-list and endorsement eligibility;
- license/copyright choice;
- funding and conflict declarations when included;
- release date.

## 5. Preprint versioning

Material scientific changes require a new arXiv version. Examples:

- corrected theorem or proof;
- corrected result/analysis;
- changed main conclusion after a parent win/null result;
- new dataset/domain added to support a broader claim;
- journal-review revision that changes scientific interpretation.

Pure typography or journal-style formatting need not define a new scientific identity.

## 6. Journal submission after arXiv

Before journal filing:

- refresh official journal rules and AI policy;
- disclose the preprint where the journal requests it;
- preserve the same claim/evidence ledger;
- explain any material changes from the current arXiv version;
- update the arXiv record after publication when appropriate.

Preprint posting does not self-grant novelty, priority beyond the dated public record, peer-review status, or journal acceptance.

## 7. No paper proliferation through preprints

A paper whose intended headline result fails does not receive a second arXiv identity merely to preserve the original positive thesis. Use the frozen negative/parent-win/merge terminal.

P-E/P-F/P-G and recursive-development papers remain governed by their existing admission/merger gates.
