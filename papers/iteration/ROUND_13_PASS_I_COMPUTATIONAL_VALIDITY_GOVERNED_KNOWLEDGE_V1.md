## 1. Editorial consequence

Pass I found that the current papers can still overstate scientific control by treating computation, uncertainty, semantic interoperability and data availability too coarsely. The paper programme must now distinguish:

- scientific model adequacy from numerical/implementation validity;
- evaluator identity from oracle and fault-detection adequacy;
- precise probability from imprecision, ignorance and conflict;
- syntactic/machine interoperability from native semantic transport;
- FAIR availability/reusability from CARE/custodial authority;
- evidence aggregation from source exclusion and question-setting power;
- held-out benchmark success from pipeline/deployment equivalence.

The correct response is not to add seven sections to every manuscript. The findings enter claim ledgers, strongest-parent baselines and protected figures only where they change the paper's central decision.

## 2. Flagship delta

### Add to parent ownership

- numerical analysis and validated numerics;
- scientific-software V&V and metamorphic/oracle methods;
- imprecise probability and uncertainty-form pluralism;
- semantic interoperability and ontology context;
- FAIR/CARE and Indigenous data sovereignty;
- epistemic injustice and participatory inquiry;
- ML underspecification/data-pipeline credibility.

### Candidate foundation pressure

The flagship's transition object must be able to distinguish the chain:

`governed source -> semantic interpretation -> scientific model -> numerical problem -> algorithm/arithmetic -> oracle/test -> output -> uncertainty -> scientific interpretation -> decision/authority`.

This chain remains a synthesis candidate, not a new main-text ontology.

### New non-claims

- reproducible computation is not numerical or scientific correctness;
- validated numerics does not validate the target-world model;
- an unavailable oracle is not a pass;
- ignorance is not a uniform probability distribution by default;
- FAIR data is not automatically authorized for reuse;
- participation is not automatic truth or independence;
- equal benchmark score is not scientific equivalence.

## 3. P-A — structural donor discovery

### Required additions

- bind donor conclusions to the computational and semantic pipeline used to reconstruct the donor;
- compare minimal envelopes with numerical conditioning, MDL/sufficiency and native semantics;
- distinguish technically accessible sources from authorized/custodially permitted donors;
- include false donors produced by ontology matching, numerical artifacts or data leakage;
- ensure multi-agent donor agreement does not substitute for source/native validity.

### Hostile cases

- structurally similar models with different conditioning;
- same ontology label, different decision constraint;
- FAIR source whose reuse is not authorized;
- remote parent missed because the source is not machine accessible;
- weak computation baseline creates false apparent novelty.

## 4. P-B — relations, competence and transport

### Required additions

- transport receipts preserve uncertainty form and numerical tolerance/error semantics;
- relation status includes computational implementation/precision when it affects the decision;
- semantic mappings bind background knowledge, local constraints and prohibited inference;
- data-use authority does not transport with scientific equivalence;
- a validated mathematical relation remains conditional on model adequacy.

### Hostile cases

- exact formal mapping with unstable numerical realization;
- interval enclosure mistaken for probabilistic confidence;
- ontology alignment that drops a local exclusion criterion;
- same scientific result but different custody/permission;
- equal benchmark score with divergent deployment behavior.

## 5. P-C — obligation-driven scientific control

### Required additions

- action selection can request higher precision, a validated enclosure, an independent implementation or a stronger oracle;
- responsibility diagnosis separates ill-conditioning, algorithm instability, implementation fault, model inadequacy and data/semantic error;
- self-model confidence uses the warranted uncertainty form rather than forcing a scalar posterior;
- robust/deep-uncertainty parent methods compete with ordinary expected-value policies;
- recovery and stopping account for computational and oracle limits.

### New task families

- `CONDITIONING_VS_IMPLEMENTATION_FAILURE`;
- `PRECISION_ESCALATION_MINIMUM_SUFFICIENT`;
- `ORACLE_ACQUISITION_VS_BLIND_RETRY`;
- `CREDAL_SELF_MODEL_VS_FALSE_PRECISION`;
- `PIPELINE_UNDERSPECIFICATION_STRESS`;
- `DATA_CASCADE_DIAGNOSIS`.

## 6. P-D — dependence-aware evidence and assurance

### Required additions

- software oracles, numerical implementations and semantic-background sources enter the dependence graph;
- conflict and ignorance remain distinct from probabilistic dependence;
- assurance cases include computational-validity and oracle-adequacy nodes;
- source exclusion and credibility rules are evaluated before evidence aggregation;
- governed-data permissions and collective authority remain separate from support strength;
- benchmark agreement must be stress-tested for underspecification.

### New task families

## 7. P-E — opportunity discovery

### Required additions

- numerical instability, software faults, semantic mismatch and data cascades are alternative explanations for anomalies;
- opportunity value cannot rely on unauthorized/custodially restricted sources;
- prospective discriminators should include computation/oracle validation;
- source exclusion can create false research gaps;
- imprecise probability and deep uncertainty may support option-preserving opportunities rather than precise ranks.

### Default contraction

P-E remains `MERGE_INTO_P-C` unless prospective independent value survives these controls.

## 8. P-F — machine-native inquiry

### Required additions

- every machine-native performance claim uses strong numerical/domain baselines and matched accuracy/resource curves;
- nonhuman internal computation exposes a claim-sufficient computational-validity witness;
- pipeline underspecification and leakage are primary hostile controls;
- different uncertainty forms may require different internal and external representations;
- source accessibility does not erase data governance;
- human-mimetic and machine-native arms are both tested for numerical, semantic and governance failures.

### Core falsifier strengthened

P-F fails if its advantage disappears after:

- matching numerical accuracy and conditioning;
- replacing weak baselines;
- controlling leakage/underspecification;
- requiring adequate oracles;
- enforcing governed source use;
- evaluating a second scientific domain.

## 9. Claim-ledger rule

Every paper claim relying on computation now binds, when material:

- mathematical problem/model;
- conditioning/error tolerance;
- method and implementation identity;
- arithmetic/precision;
- oracle/test adequacy;
- uncertainty form;
- native semantic scope;
- source governance;
- strongest baseline;
- deployment/stress scope.

An omitted field is acceptable only with an explicit irrelevance argument or non-application control.
