# Round 15 — Knowledge Metabolism and Real-Problem Evidence Programme V1

**Status:** recursive paper iteration driven by a new executable lifecycle and frozen real-problem protocol. It does not promote any empirical claim or journal readiness.

## 1. Scientific correction

ORION-V2 already contained separate mechanisms for:

- native reconstruction;
- donor reduction;
- decision-relative envelopes;
- typed relation and transport;
- provenance and dependence;
- counter-probes;
- selective reopening;
- component-value evaluation.

What was missing was one explicit end-to-end lifecycle connecting those mechanisms in the order suggested by the user’s digestion and recycling analogies:

```text
mixed source material
→ typed decomposition
→ conservative sorting
→ native parent recovery
→ parent reduction
→ selective absorption
→ recombination
→ challenge
→ assimilation or negative-knowledge recycling
```

This gap is now represented by `src/orion_v2/knowledge_metabolism.py`. The metaphor is explanatory; the scientific claim depends on component and real-problem evidence.

## 2. Programme-wide evidence gate

The new runner and registry establish three evidence layers:

### E0 — reference semantics

- source identities preserved;
- duplicate content does not erase provenance or dependence;
- weakest authority ceiling conserved;
- missing native recovery blocks absorption;
- missing discriminator/falsifier blocks recombination;
- parent refutations are retained as negative knowledge;
- strict residuals receive only `READY_FOR_PROTECTED_EVALUATION`.

### E1 — executable real-problem pilot

- exact benchmark checkout;
- gold-blind solver workspace;
- arm-specific request and response schema;
- fresh native evaluator workspace;
- patch/solution execution;
- fail-closed missing-agent/data/evaluator terminal.

### E2 — protected cross-domain result

- matched F0/direct/reflection/F2 and ablation arms;
- independent adjudication;
- resource curves;
- anti-copy counterfactual controls;
- at least two materially different domains;
- complete negative and parent-win reporting.

Only E2 can support the central paper claims.

## 3. Flagship propagation

### New explanatory device

Use “knowledge metabolism” sparingly to explain why the field operates below document-level retrieval:

- sources are decomposed into claims, assumptions, methods, relations and constraints;
- native validity is recovered before reuse;
- elements are selectively recombined;
- proposed synthesis is challenged before adoption;
- invalid or irrelevant material remains available as negative history rather than disappearing.

### Main-text limit

The flagship should not claim a biological theory of knowledge or present the metaphor as evidence. It should state one empirical consequence:

> A higher-order scientific system should outperform passage-level or monolithic reasoning specifically when valid problem solving requires preserving and recombining heterogeneous epistemic roles.

## 8. P-E propagation — generative recombination

P-E tests whether atom/relation recombination produces prospective scientific opportunities beyond retrieval, parent search, anomaly detection and expert brainstorming.

The metabolism lifecycle creates a precise serendipity route:

```text
unexpected source atom or failure residue
→ retained source-bound candidate
→ bridge to unresolved problem
→ recombination
→ discriminator
→ prospective outcome
```

P-E remains standalone only when future value survives outcome-blind evaluation. Otherwise this mechanism stays inside P-C/P-G.

`P_E = CONTINGENT`.

## 9. P-F propagation — machine-native problem solving

P-F tests whether machine-native internal computation can exploit the decomposed/recombinable state more effectively than human-trace imitation while producing the same external scientific witness.

Required evidence:

- gold-blind executable tasks;
- newly generated counterfactual variants;
- network/retrieval controls;
- resource-matched human-mimetic and parent-native systems;
- internal-strategy difference documented without treating opacity as value;
- causal ablations showing the machine-native representation or search process caused the gain.

`P_F = PROSPECTUS_ONLY__RUNNER_INTERFACE_AVAILABLE`.

## 12. Anti-copy claim discipline

The programme may claim only convergent evidence of active problem solving. It cannot prove a model has never seen related training material.

Strong evidence includes:

- gold withheld;
- fresh workspaces;
- newly seeded private permutations;
- hidden tests/interventions;
- execution success;
- source-use receipts;
- network-off and retrieval-off controls;
- correct transfer to counterfactual variants;
- low or nonessential dependence on exact gold-patch text.

Do not use reasoning length, stylistic novelty or self-reported originality as primary evidence.
