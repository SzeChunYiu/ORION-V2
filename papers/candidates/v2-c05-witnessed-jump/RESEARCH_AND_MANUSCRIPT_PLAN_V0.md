# V2-C05 Research and Manuscript Plan V0

**Working title:** *Witnessed Scientific Jump: Minimum-Level Search-Space Evolution*  
**Status:** high-risk candidate; all claims `CANNOT_CHECK`.

## 1. Starting boundary

ORION V1 already demonstrated a bounded distinction between search/model expansion inside a frozen representation and a validated transition beyond it, while finding no incremental ORION value over the strongest verified regime-revision parent. Broad creativity labels were decomposed into multiple operations.

Therefore this paper cannot claim a primitive `JUMP()` or generic creativity, reframing, analogy, open-endedness or self-improvement.

## 2. Candidate thesis

A controller can prospectively identify the minimum search-space level responsible for a scientific impasse, select the lowest sufficient transformation, preserve or explicitly reopen prior commitments, and improve justified reachability over lower-level, unconstrained-Jump and strongest donor-composed baselines.

## 3. Escalation ladder

- J0 action/parameter/query/experiment;
- J1 local repair or known-method composition;
- J2 model/hypothesis expansion;
- J3 representation/abstraction/regime transition;
- J4 problem/objective/constraint reformulation;
- J5 method/operator/tool/instrument invention;
- J6 workflow/control/meta-skill revision;
- J7 framework revision;
- J8 constitution proposal, externally authorized only.

## 4. Formal objects

### `IncumbentClosure`
Registered objects, actions, model grammar, representations, objectives, tools, workflow, framework and evaluator/authority epoch.

### `InsufficiencyWitness`
Exact obstruction, non-identifiability, counterexample, model criticism, repeated residual or transport failure plus competing lower-level explanations.

### `JumpTrigger`
Current level, closure, witness, coverage/censoring, responsibility discriminator and proposal-only state.

### `JumpProposal`
Transformation, parent lineage, correspondence, affected commitments, preservation/reopening, predicted new contracts, cost/risk, falsifiers and rollback.

### `JumpEvaluationReceipt`
Frozen proposal/evaluator, incumbent and donor-product baselines, ceiling result, fresh reach, preservation, semantic fidelity, false-escalation controls, replay and external adoption.

## 6. Benchmark ladder

### Tier J0
Direct/native method succeeds. Any higher escalation is false Jump.

### Tier J1
Implementation, interface, evidence identity or local composition repair.

### Tier J2
Old representation adequate; model family incomplete.

### Tier J3
No model in the old representation can express the protected solution; correspondence and old/new consequences are testable.

### Tier J4
Current problem/objective/proxy is responsible, not implementation or model family.

### Tier J5
A new operator, algorithm, proof rule, measurement channel or instrument is required.

### Tier J6
The action-generation/selection/evaluation process is responsible.

### Tier J7
The framework’s schema/operator/dependency/provenance/history/policy envelope is responsible.

### Tier J8
Protected validation/authority/integrity rules are implicated; proposal allowed, self-certification prohibited.

Every tier includes matched public symptoms with different hidden responsible levels.

## 10. Baselines

- never Jump;
- Jump after N failures;
- scalar surprise/uncertainty trigger;
- LLM “rethink creatively”;
- fixed-level representation change;
- strongest level-specific parent;
- strongest donor-composed escalation policy;
- candidate controller;
- oracle responsible level for ceiling analysis only.

## 11. Critical negative controls

- missing evidence mistaken for expressive ceiling;
- censored search mistaken for impossibility;
- local implementation bug mistaken for J7;
- J2 sufficient but J3 proposed;
- new name/macro treated as J5;
- evaluator manipulation treated as J4 progress;
- proposal generated after protected leakage;
- valid new solution with invalid old-knowledge transport;
- current-task gain with later-successor harm;
- multiple incomparable successors.
