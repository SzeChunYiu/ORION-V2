# V1 Capability Disposition Matrix V0

**Status:** planning census; exact V1 binding remains blocked by issue #2.  
**Purpose:** prevent feature loss while allowing complete V2 refactoring.

## Rule

V2 does not owe V1 atom or workflow parity. It owes **scientific capability parity**. Every useful frozen V1 capability must receive one evidence-bound disposition:

- `PRESERVE_NATIVE`
- `PRESERVE_AS_SPECIAL_CASE`
- `MERGE_INTO_DEEPER_OBJECT`
- `SPLIT_BY_CONTEXT`
- `REPLACE_WITH_PARENT_METHOD`
- `REPLACE_WITH_DONOR_PRODUCT`
- `GENERALIZE_WITH_NEW_COORDINATE`
- `DEPRECATE_AFTER_PROTECTED_NONINFERIORITY`
- `CANNOT_CHECK`

No current row is an adoption decision.

## New capability families absent or weak in the V1 root runtime

- frontier opportunity and question generation;
- explicit live hypothesis/model/solution portfolios;
- coupled hypothesis–experiment search;
- cross-action value-of-information selection;
- multiple-fault/distributed responsibility;
- context-relative relation and distinguishing-probe engine;
- physical and computational experiment orchestration;
- formal synthesis/counterexample/refinement loops;
- diversity/open-ended archive control;
- strategic/performative environment modelling;
- dependence-aware evidence and validator diversity;
- cross-generation comparability certificates;
- reticulate multi-parent provenance;
- meta-solver/meta-skill evolution;
- post-adoption monitoring and reopening.

## Gate

This matrix cannot be finalized until:

1. issue #2 binds exact V1 identities;
2. an executable V1 capability census is generated from frozen APIs and papers;
3. all-domain parents are reconstructed;
4. known-answer/hostile cases are frozen;
5. V1, parent, strongest donor product and candidate V2 are compared under matched resources.
