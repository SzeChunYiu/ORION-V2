# MEG-36 V1 — operator/certificate behavior identity and epistemic drift

Status: **FOUNDATION CANDIDATE.**
Parent issue: `#319`. New foundation identity: `MEG-36`.
Checker: `machine_epistemics_foundation_v1_check.py`.
No novelty claim: this is a fail-closed provenance/versioning contract specialized to epistemic certificates.

## 0. Problem

A certificate is evidence about a behaviorally specified procedure.

If a model, implementation, prompt, decoder, quantization mode, checker, calibration split, assumptions, scope, epoch or other behaviorally decisive runtime component changes while the certificate identity remains unchanged, the machine can reuse evidence for a procedure that was never validated.

That is epistemic drift.

A short public operator id plus semantic version is not a sufficient certificate identity.

## 1. BehaviorIdentityV1

A certificate-bound operator/pipeline identity is the content digest of the tuple:

1. `implementation_digest`
   - executable/source/build identity;
2. `model_digest`
   - exact model/weights or explicit `NONE`;
3. `configuration_digest`
   - prompt/template, decoding settings, temperature, sampling, quantization and other behavior-changing configuration;
4. `runtime_digest`
   - relevant dependency/environment/resource-policy manifest;
5. `checker_digest`
   - exact evaluator/verifier implementation and version;
6. `calibration_digest`
   - calibration data identity, method, split, seed and preprocessing;
7. `assumption_digest`
   - exchangeability/shift/independence/causal and other validity assumptions;
8. `scope_digest`
   - domain/task/population/authority scope;
9. `epoch`
   - validity epoch or explicit timeless sentinel justified by the study.

Every component is mandatory. Non-applicability is represented by an explicit sentinel such as `NONE`, not an omitted field.

`behavior_digest = SHA256(canonical_json(BehaviorIdentityV1))`.

## 2. MEG-36A — exact reuse rule

A certificate bound to behavior digest `b` is reusable for an invocation only if the invocation's recomputed behavior digest is exactly `b` and the certificate's scope/assumption/epoch bindings match the active policy.

This rule is deliberately syntactic/content-addressed. It avoids asking a runtime to guess whether two changed implementations are "close enough".

A future V2 study may register a sound semantic-equivalence certificate that permits reuse across different digests. Until then, digest inequality is fail-closed.

## 3. MEG-36B — drift terminals

If a required component is present and differs, route to `REVALIDATE_*`.

If a required component cannot be reconstructed or is missing, route to `CANNOT_CHECK`.

No mismatch may route directly to VALID/LIVE/AUTHORIZED.

The checker mutates each of the nine bound fields independently and confirms that the old certificate is rejected.

## 4. MEG-36C — checker identity is part of evidence identity

A checker can drift too.

A certificate generated by checker `V1` is evidence about `V1`'s decision procedure. Replacing it with `V2` without an explicit equivalence/supersession result invalidates certificate reuse, even when the model/operator is byte-identical.

This prevents evaluator drift from laundering old warrants into a new verification regime.

## 5. MEG-36D — calibration identity is composite

For calibrated/statistical operators, `calibration_digest` binds at least:

- data/corpus digest;
- labels/ground truth version where applicable;
- split membership/order if semantically relevant;
- preprocessing/feature pipeline;
- random seed(s);
- calibration algorithm and hyperparameters;
- target guarantee/risk level.

Changing any of these requires a new calibration identity unless a theorem explicitly proves invariance to that component.

## 6. Configuration shift

For neural/LLM pipelines, the calibrated procedure includes the inference configuration.

Prompt templates, decoding temperature and weight quantization are therefore certificate-bound configuration, not comments.

Recent conformal-LLM evidence shows these changes can degrade empirical coverage. Foundation V1 does not rely on that empirical paper as a universal theorem; it uses the result as a hostile example supporting the fail-closed identity design.

## 7. Resource/environment binding

`runtime_digest` includes only environment/resource properties that can affect behavior or the guarantee.

Examples may include:

- dependency versions;
- precision/dtype;
- hardware-specific kernels when nondeterminism or numerical behavior matters;
- timeout/search budget;
- tool/version manifest;
- sandbox policy.

A study that proves invariance to a component may exclude it, but the exclusion itself must be in the registered assumption/identity specification.

## 8. Supersession

A new certificate never overwrites the old one.

It is appended with:

- new behavior digest;
- lineage/supersedes relation;
- reason for revalidation;
- exact study/checker/receipt.

Historical state stays inspectable.

## 9. OCM absorption rule

Every `OperatorSpec` or equivalent runtime object that can consume a certificate must expose or deterministically derive `BehaviorIdentityV1`.

An OCM parity test must mutate at least:

- model/implementation;
- configuration/prompt;
- checker;
- calibration identity;
- assumption set;
- scope;
- epoch.

Every mutant must route to revalidation or `CANNOT_CHECK`.

## 10. Non-consequences

This contract does not say that any two different digests are semantically different. It says the machine lacks authority to assume equivalence without a registered equivalence result.

It does not solve distribution shift. It ensures shift-relevant changes cannot remain invisible to certificate validity.
