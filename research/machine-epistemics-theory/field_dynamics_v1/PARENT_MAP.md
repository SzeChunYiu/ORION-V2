## 3. Exact parent reductions already visible

### 3.1 Warrant/provenance

The antichain-support algebra is a specialized provenance/ATMS object. Machine Epistemics adds typed authority, scope, explicit `UNKNOWN`, certificate identity, failure terminals and a disciplined V2→OCM use contract; none of those facts by itself makes the underlying semiring novel.

### 3.2 Multiscale navigation

For finite state-only projection, cross-scale restart dynamics reduce to strong lumpability/intertwining. Machine Epistemics adds the independent requirement that warrant/liveness and the registered answer functional also factor through the projection. If a future multiscale object is representable by a finite fine kernel plus projection, parent sufficiency is expected.

### 3.3 Persistence and viability

The finite persistent-validity kernel is ordinary safety/reachability. The controlled extension is naturally a viability/safety-game kernel after the epistemic admissibility predicate and action set are specified. The likely scientific residual is therefore not the viability algorithm but the **typed construction of the admissible set and transition interface**—and even that may be a useful integration with no architecture residual.

### 3.4 Causal claims

Observation, intervention and counterfactual identification are parent-owned causal-inference objects. Machine Epistemics contributes lifecycle/provenance/authority integration only if that integration creates a theorem not already covered by dynamic probabilistic logic, provenance or causal databases.

### 3.5 Active epistemic control

Querying, experimentation and clarification can be mapped to information-acquisition actions in a belief-state decision problem. Any claim that an OCM-specific controller is new must beat this formulation under matched observation, model and resource access.

## 4. Where a residual could still exist

The strongest candidate residual is **not one primitive**. It is a theorem about the coupled product:

`warrant/provenance × partial model × representation certificate × revision dynamics × resource accounting × external authority`.

Candidate residual questions:

1. Does the typed product admit a representation/revision theorem that is strictly stronger than applying the parent components independently?
2. Is there a natural lifecycle-learnability separation once future revocation behaviour is part of the target equivalence?
3. Can proof-carrying local traces produce a strict information/resource frontier versus the strongest equal-access learner?
4. Is there a nontrivial lower bound for maintaining query-relative certified representations under changing obligations?
5. Does a self-model/representation-change controller retain a residual after comparison with verified program synthesis + algorithm selection + external evaluation?

If the answer is no, the correct global result is `FORMALISM_USEFUL_NO_ARCHITECTURE_RESIDUAL` or `PARENT_SUFFICIENT`.

## 5. Non-negotiable subtraction rules

- Compare against **compositions** of parents, not isolated mechanisms.
- Give parents the same memory, verifier, tools, observations, intervention access and adaptive-step budget.
- Count parser/renderer, index, certificate, model-class and preprocessing information.
- A mathematical restatement in hypergraph/category vocabulary is not a residual.
- A finite exact implementation match is not a novelty result.
- A negative/equivalence theorem is a successful field result.
