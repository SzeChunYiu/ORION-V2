## 3. Exact parent reductions already visible

### 3.1 Warrant/provenance

The antichain-support algebra is a specialized provenance/ATMS object. Machine Epistemics adds typed authority, scope, explicit `UNKNOWN`, certificate identity, failure terminals and a disciplined V2→OCM use contract; none of those facts by itself makes the underlying semiring novel.

### 3.2 Multiscale navigation

For finite state-only projection, cross-scale restart dynamics reduce to strong lumpability/intertwining. Machine Epistemics adds the independent requirement that warrant/liveness and the registered answer functional also factor through the projection. If a future multiscale object is representable by a finite fine kernel plus projection, parent sufficiency is expected.

### 3.3 Persistence and viability

The finite persistent-validity kernel is ordinary safety/reachability. The controlled extension is naturally a viability/safety-game kernel after the epistemic admissibility predicate and action set are specified. The likely scientific residual is therefore not the viability algorithm but the **typed construction of the admissible set and transition interface**—and even that may be a useful integration with no architecture residual.

### 3.4 Causal claims

Observation, intervention and counterfactual identification are parent-owned causal-inference objects. Machine Epistemics contributes lifecycle/provenance/authority integration only if that integration creates a theorem not already covered by dynamic probabilistic logic, provenance or causal databases.

### 3.5 Active epistemic control

Querying, experimentation and clarification can be mapped to information-acquisition actions in a belief-state decision problem. Any claim that an OCM-specific controller is new must beat this formulation under matched observation, model and resource access.

## 4. Where a residual could still exist

The strongest candidate residual is **not one primitive**. It is a theorem about the coupled product:

`warrant/provenance × partial model × representation certificate × revision dynamics × resource accounting × external authority`.

Candidate residual questions:

1. Does the typed product admit a representation/revision theorem that is strictly stronger than applying the parent components independently?
2. Is there a natural lifecycle-learnability separation once future revocation behaviour is part of the target equivalence?
3. Can proof-carrying local traces produce a strict information/resource frontier versus the strongest equal-access learner?
4. Is there a nontrivial lower bound for maintaining query-relative certified representations under changing obligations?
5. Does a self-model/representation-change controller retain a residual after comparison with verified program synthesis + algorithm selection + external evaluation?

If the answer is no, the correct global result is `FORMALISM_USEFUL_NO_ARCHITECTURE_RESIDUAL` or `PARENT_SUFFICIENT`.

## 5. Non-negotiable subtraction rules

- Compare against **compositions** of parents, not isolated mechanisms.
- Give parents the same memory, verifier, tools, observations, intervention access and adaptive-step budget.
- Count parser/renderer, index, certificate, model-class and preprocessing information.
- A mathematical restatement in hypergraph/category vocabulary is not a residual.
- A finite exact implementation match is not a novelty result.
- A negative/equivalence theorem is a successful field result.

`GENERAL_NOVELTY = NOT_ESTABLISHED`.

## 6. Executable parent product and exact boundaries

The finite product reconstructed here takes registered assumptions as inputs:

| Coordinate | Parent operation | Exact executable consequence | Boundary retained |
|---|---|---|---|
| Warrant and dependence | Alternative support sets, idempotent union, nogood filtering | `warrant_status`; unknown/unregistered roots and joint contradiction tests | No fabricated root truth; no scalar-product assumption of independence |
| Authority | Finite meet order on derivation ceilings | `authority_preserved` accepts/rejects a supplied output | No verification of external source legitimacy |
| Revision | Reachability through declared dependencies | `impact_cone` handles cycles/multi-head edges | No theorem about hidden dependencies or unknown fixed-point selection |
| Fast inference | Exact rational restart linear system | `fixed_point`, FD-04 bound | Substochastic/nonnegative/unit-seed hypotheses enforced |
| History | Append-only event sequence plus active-set projection | Revoke/reinstate semantic equality, audit inequality | No inverse on full history/cost state |
| Control | Finite safety-game greatest fixed point | `controlled_kernel`; independent policy/reachability oracle | Controller moves first; every environment successor matters; closed model required |
| Learning | Finite deterministic-channel fibres and entropy | `channel_update`, integer expected-information bound | Uniform prior; realised rare outcome bound is explicitly refuted |
| Representation | Strong lumpability plus refinement map | `strong_lumpable`, `revision_commutes` | Measurable answers/warrants and every revision remain separate obligations |
| Shadow governance | Declared write footprint | `shadow_noninterfering` rejects world/commit changes | Contract check, no concurrent-runtime proof |
| Resources and termination | Additive expenditure, well-founded fuel | `resource_add`, `run_pipeline` | Fixed units/axes; cyclic or blocking external runtime beyond model |

Their composition is a typed product with interface obligations: E changes a
registered support and computes the dependency cone; F recomputes on the fixed
snapshot; R needs both navigation and epistemic/revision preservation; G checks
the safe set and external permission while B meters every step. A missing
interface premise yields `CANNOT_CHECK`. The product does not prove that a
runtime dispatches these checks, that any deployment has a closed world model,
or that the combined system dominates the strongest parent composition.

Primary anchors inspected for the newly explicit reductions:

- [Shannon, A Mathematical Theory of Communication (1948)](https://people.math.harvard.edu/~ctm/home/text/others/shannon/entropy/entropy.pdf): discrete channel and entropy assumptions; used only for the finite expected-information fragment.
- [Jacobi and Görnerup, A dual eigenvector condition for strong lumpability of Markov chains (2008)](https://arxiv.org/html/0710.1986v2), Theorem 1: equality of block-transition sums. The provenance and revision gates are additional registered observables, not consequences of lumpability alone.
- [Bernstein and Dall'Anese, Asynchronous and Distributed Tracking of Time-Varying Fixed Points (2018)](https://arxiv.org/abs/1804.09768v2): parent ownership of contraction tracking, including missing/asynchronous information under its own hypotheses.
- [Narodytska et al., Solving Games without Controllable Predecessor (2014)](https://www.cs.cmu.edu/~ryzhyk/publications/Narodytska_LBRW_14.pdf): controller/environment safety-game setting. This package reconstructs the elementary predecessor fixed point, without claiming their algorithm.
- [Abadi and Lamport, The Existence of Refinement Mappings](https://lamport.azurewebsites.net/pubs/abadi-existence.pdf): state refinement and the separation of safety requirements from liveness requirements. Finite footprint preservation is not a termination theorem.

These references establish relevant parent objects, not an exhaustive priority
search. The broad atlas includes causal/linguistic parents for programme context;
this execution package neither implements those domains nor declares their
remaining research complete.
