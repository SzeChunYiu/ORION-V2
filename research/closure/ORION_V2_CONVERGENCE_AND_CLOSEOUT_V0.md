# ORION-V2 Convergence and Closeout Programme V0

**Status:** Wave 06 contraction/optimization. The V1 handoff is bound for local reference implementation and prospective protocols; protected external scientific evaluation, novelty promotion and final publication authority remain separate.

## 1. Why the programme must now contract

Waves 01–05 materially changed the object under study:

- Wave 01 built the cross-domain structural atlas, typed research objects and V1 parity census;
- Waves 02–03 moved from donor collection to decision-preserving generalization and conservative target adaptation;
- Wave 04 added native-decision recovery as a reverse validation requirement;
- Wave 05 generalized exact transport to stochastic/approximate transport with explicit decision-margin and epoch checks.

The programme is therefore no longer blocked by a lack of candidate mechanisms. The dominant risks are now:

1. duplicate abstractions and module proliferation;
2. paper fragmentation around coordinates that are components of one scientific object;
3. authored reference methods replacing stronger parent implementations;
4. stacked draft PRs obscuring the actual candidate state;
5. perpetual donor expansion without a bounded stop rule;
6. local known-answer success being mistaken for protected scientific value.

Wave 06 treats **contraction as progress**.

## 2. Current strongest scientific picture

The smallest defensible candidate is not a universal ontology. It is a scientific control kernel that coordinates parent-owned methods through typed contracts and receipts.

The candidate irreducible obligations are:

1. **bind the scientific decision/problem and authority boundary**;
2. **preserve a plural scientific state rather than forcing premature collapse**;
3. **state exactly what relation/transport is claimed and under which context, probes, epoch and tolerance**;
4. **preserve evidence dependence, provenance, assumptions and counterexamples**;
5. **select and execute admissible actions while keeping execution, verification, validation and authority distinct**;
6. **diagnose whether failure belongs to evidence, model, representation, method, workflow or framework before escalation**;
7. **reopen only what a changed assumption/evidence/configuration actually invalidates**;
8. **stop with a typed terminal instead of forcing success**;
9. **compare every apparent ORION mechanism against the strongest parent-composed alternative**;
10. **preserve all V1 and V2 negative history and non-retroactivity**.

Everything else is a candidate adapter, policy, parent implementation or paper-specific method until protected evidence proves otherwise.

## 3. Contraction target for the code architecture

### Kernel K0 — identity, contracts and immutable receipts

Owns stable object identity, problem/decision contract, obligations, epochs, resource/authority declarations and immutable execution/evidence receipts.

### Kernel K1 — plural scientific state

Owns live hypotheses/models/solutions, unresolved alternatives, support/defeaters, uncertainty/identifiability state and historical negative knowledge.

### Kernel K2 — relation and transport interface

Owns the *typed request* for isomorphism/equivalence/indistinguishability/comparability/abstraction/transport and the receipt returned by a parent method. Exact finite, stochastic and approximate reference models remain tests/baselines, not universal defaults.

### Kernel K3 — evidence, dependence and provenance interface

Owns evidence units, dependence/common-cause structure, component lineage, assumption/counterexample inheritance, authority ceilings and invalidation reach.

### Kernel K4 — solver, action and recovery interface

Owns admissible action proposals, non-compensatory selection, execution binding, diagnosis topology, workflow constraints, compensation/retry/repair and selective reopen.

### Kernel K5 — frontier and escalation interface

Owns research-opportunity proposals, portfolio status and witnessed escalation. Domain-specific ideation, optimization, theorem proving, design search and experiment design stay parent-owned.

### Kernel K6 — evaluation, parity, saturation and authority

Owns V1 parity dispositions, protected benchmark identity, donor-product comparison, multidimensional saturation, scientific-authority boundary and publication projection.

## 4. Explicit non-kernel components

The following should default to parent adapters rather than ORION-native reinvention:

- optimization, scheduling, queueing and portfolio solvers;
- workflow/process engines;
- causal discovery and causal inference algorithms;
- formal theorem provers, CEGAR/CEGIS and program synthesis engines;
- probabilistic abstraction metrics and robust-control algorithms;
- metrology/calibration libraries;
- generic provenance graph stores;
- diagnosis engines and reliability models;
- psychometric/political linking models;
- domain ontologies and domain-specific theory objects;
- laboratory/instrument drivers;
- literature retrieval/indexing systems.

ORION-V2 may define the typed adapter contract and scientific obligations around these systems. It should not claim the underlying parent algorithms.

## 6. Closeout gates

V2 is not considered closed merely because the reference suite is green. The closeout sequence is:

### G0 — exact V1 handoff

Already bound for local reference implementation/prospective protocols. Non-retroactivity remains permanent.

### G1 — V1 capability parity

Every frozen V1 capability has a final disposition and protected non-regression result where required. Simple controls must punish unnecessary V2 complexity/escalation.

### G2 — paper contraction

Every candidate has a terminal: standalone, merged, methods/resource, parent-subsumed or `CANNOT_CHECK`. No orphan candidate remains merely because a directory/issue exists.

### G3 — minimal kernel freeze

Every kernel coordinate has a downstream sufficiency role. Duplicate types/APIs are eliminated or explicitly compatibility-scoped. Parent-owned mechanisms sit behind adapters.

### G4 — strongest parent baselines

Each surviving scientific claim is compared with the strongest compatible donor product, not a weak single baseline.

### G5 — protected evaluation

Prospective evaluation covers V1 parity, direct controls, native recovery, cross-domain transfer, approximate/stochastic transport, dependence, solver behaviour, escalation and frontier opportunity where applicable.

### G6 — bounded saturation

After Wave 06, require **two complete changed-vocabulary/hostile contraction passes** that add no material coordinate, relation, obstruction, failure mode, parent contraction, benchmark family or paper identity. Censored routes remain explicit.

### G7 — failure closure

No critical correctness/integrity/authority defect remains unresolved. Valid scientific negative results and external `CANNOT_CHECK` may remain if explicitly ledgered.

### G8 — external scientific/publication authority

Internal closeout cannot self-grant novelty, publication or field acceptance. These remain external even after the architecture is locally closed.

## 7. Work-order optimization

The optimal work order is not the gate order.

1. contract papers immediately;
2. freeze the minimal kernel/API surface;
3. collapse/supersede stacked PRs into one convergence PR;
4. update stale issue status language;
5. finish parent-composed baselines;
6. freeze protected evaluation protocols;
7. run parity and protected campaigns;
8. execute two no-material-change saturation passes;
9. issue the final architecture/paper/failure ledgers;
10. seek external scientific/publication authority.

## 8. No-new-wave rule

After Wave 06, a new wave is permitted only when a named closeout blocker cannot be discharged inside the convergence branch. New donor discoveries that merely refine a parent bibliography are absorbed into the existing lane rather than creating a new framework component or paper.
