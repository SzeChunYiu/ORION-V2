# Machine-X Demarcation / Frontier Verification Protocol V1

**Status:** prospective, bounded verification of the machine-X demarcation and obstruction-first frontier interpretation. This protocol does not alter frozen P-A–P-D primary endpoints or claim that Machine Epistemics is superior to machine learning/intelligence.

## 1. Scientific question

Does explicitly separating **capability**, **learning/action mechanism**, and **epistemic transition control** improve action selection on frontier episodes where the kind of missing object is hidden?

The strongest null is that ordinary context-conditioned metareasoning, the current F0 parent federation or current F2 already performs the same routing at equal/lower cost.

## 2. What is not being tested

This protocol does not attempt to prove:

- a universal definition of intelligence;
- that Machine Epistemics is a higher intelligence level;
- that machine learning is a subset or inferior field;
- that every frontier problem needs explicit ORION control;
- that the machine-X terminology is universally accepted.

## 3. MX10 — code/interface hardening

MX10 consists of deterministic unit/interface checks:

- neighboring machine-X concepts have distinct categorical roles but no ordering;
- capability claims require a declared locality context;
- `LEARN`, `PROVE`, `MEASURE`, etc. remain ordinary existing-control actions;
- representation/problem/tool/workflow transforms route to the existing Jump interface;
- regime transforms require an explicit transform scope;
- transformation routing is blocked until lower-level routes are dispositioned;
- abstention remains a valid action;
- no route authorizes scientific truth or intelligence superiority.

Current implementation surface:

`tests/unit/test_epistemic_architecture_wave6.py`

MX10 is a semantic guardrail, not an empirical field result.

## 4. MX20 — exact hidden-obstruction benchmark

### 4.1 Design principle

The task should hide **what kind of thing is missing**, not merely hide an answer.

Each finite case has a known scientific obstruction and an exact or exhaustively checkable action-family oracle.

### 4.2 Required case families

At minimum include cases where the minimum sufficient response is:

1. `LEARN_OR_ESTIMATE` — the existing representation/evaluator are adequate and a learned estimator/policy is sufficient;
2. `REASON_OR_PROVE` — additional data fitting is unnecessary; an exact argument/counterexample resolves the obligation;
3. `MEASURE_OR_EXPERIMENT` — missing evidence must come from the world;
4. `MODEL_EXPANSION` — incumbent hypothesis/model class is too narrow;
5. `REPRESENTATION_OR_PERSPECTIVE_CHANGE` — the current state variables/boundary/scale collapse decision-distinct cases;
6. `PROBLEM_REFORMULATION` — the registered question is ill-posed or targets the wrong discriminator;
7. `TOOL_OR_INSTRUMENT_CONSTRUCTION` — current observations/interventions cannot identify the alternatives;
8. `WORKFLOW_OR_META_SKILL_CHANGE` — action-generation/control structure is the blocker;
9. `NO_ESCALATION` — a simple/native or parent method is already sufficient;
10. `ABSTAIN_OR_CANNOT_CHECK` — no admissible action can support a warranted terminal under current authority/resources.

Reuse exact GR10 generative-regime and EL10 locality fixtures where their oracles match these families. Do not duplicate cases merely to increase sample count.

### 4.3 Arms

Prospectively bind matched information/resources for:

- `SIMPLE_DIRECT`;
- `ML_ONLY_OR_TASK_OPTIMIZER` where a faithful task-level learner exists;
- `SAME_MODEL_REFLECTION`;
- `F0_PARENT_FEDERATION`;
- `CURRENT_F2`;
- `F2_OBSTRUCTION_ROUTING` only if it can be implemented as a separable interface delta rather than a prompt-label change.

If `F2_OBSTRUCTION_ROUTING` is behaviorally identical to current F2, the correct disposition is `NO_NEW_COMPONENT`; do not manufacture a separate arm.

### 4.4 Primary outcomes

Use the registered case as the independent unit. Report:

```text
obstruction_class_correctness
action_family_correctness
minimum_responsible_level_correctness
false_jump_rate
missed_jump_rate
justified_terminal_correctness
critical_false_completion
predecessor_preservation
resource_cost
```

Critical false completion and predecessor regression are non-compensatory.

### 4.5 Key contrasts

1. Does ML-only optimization fail specifically when the learning problem itself is malformed, while remaining strong on genuinely learnable cases?
2. Does explicit obstruction diagnosis improve action routing beyond current F0/F2?
3. Does the extra interface increase false escalation on simple/native cases?
4. Are gains merely labels/prompts, or do they survive renamed action/obstruction vocabularies?

### 4.6 Kill conditions

The explicit frontier-demarcation interface contracts if:

- `CURRENT_F2` already matches it;
- `F0_PARENT_FEDERATION` matches/exceeds it at lower/equal cost;
- gains disappear under renamed formulation;
- gains arise only because the correct action taxonomy is leaked to the solver;
- false-Jump or predecessor-regression cost offsets the claimed benefit.

Valid terminal:

`MACHINE_X_DEMARCATION_USEFUL_FOR_EXPLANATION_ONLY`.

## 5. MX30 — naturalistic frontier transfer

**Not authorized by default.**

Open only if MX20 demonstrates a protected residual beyond current F0/F2 that is not explained by benchmark vocabulary or stronger parent routing.

Candidate naturalistic cases must be prospectively bound and independently certified to contain uncertainty about the obstruction class. A real scientific case where the answer is difficult but the missing action is obvious does not test the proposed residual.
